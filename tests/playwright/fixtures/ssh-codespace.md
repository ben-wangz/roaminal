# SSH and tmux codespace fixture

This fixture is the controlled OpenSSH target for the SSH and tmux Playwright
cases. It is a disposable Kubernetes workload, not a product dependency and
not a user workspace. The fixture must be reset before every suite run so a
previous shell, tmux server, host key, or test marker cannot affect the result.

The fixture is installed from the published `codespace` Chart maintained by
the [k8s-at-home project](https://github.com/ben-wangz/k8s-at-home). Do not use
port forwarding. Roaminal connects to the fixture's ClusterIP Service from its
Pod network.

## Ownership and variables

Use a dedicated fixture release by default. The existing `roaminal-codespace`
workload in `develop` may be adopted only when the operator explicitly chooses
the migration below and accepts that its Deployment, Service, Secret, and
ephemeral home are reset. Never delete a resource only because its name
contains `codespace`; verify the exact labels first.

```bash
export ROAMINAL_E2E_SSH_FIXTURE_RELEASE="roaminal-e2e-codespace"
export ROAMINAL_E2E_SSH_FIXTURE_NAMESPACE="${ROAMINAL_E2E_NAMESPACE:-develop}"
export ROAMINAL_E2E_SSH_FIXTURE_SECRET="${ROAMINAL_E2E_SSH_FIXTURE_RELEASE}-authorized"
export ROAMINAL_E2E_SSH_FIXTURE_CHART_VERSION="0.1.7"
export ROAMINAL_E2E_SSH_USER="root"
export ROAMINAL_E2E_SSH_PORT="22"
export ROAMINAL_E2E_SSH_ALIAS="codespace-e2e"
export ROAMINAL_E2E_TMUX_ALIAS="codespace-e2e-tmux"
export ROAMINAL_E2E_TMUX_SESSION="roaminal-e2e"
export ROAMINAL_E2E_SSH_HOST="${ROAMINAL_E2E_SSH_FIXTURE_RELEASE}-ssh.${ROAMINAL_E2E_SSH_FIXTURE_NAMESPACE}.svc.cluster.local"
```

The exact release and namespace are part of the test report. If the fixture
uses another fullname, obtain the Service name from the Helm release and set
`ROAMINAL_E2E_SSH_HOST` to that Service's DNS name. Never infer a node IP.

### Adopting the pre-provisioned `develop` target

The cluster may already contain the test target from an earlier manual
installation. It is not Helm-owned, so `helm uninstall` cannot clean it. To
make it a reproducible fixture, use the exact resource names and labels below;
do not run a broad `kubectl delete -l app.kubernetes.io/name=codespace`:

```bash
export ROAMINAL_E2E_SSH_FIXTURE_RELEASE="roaminal-codespace"
export ROAMINAL_E2E_SSH_FIXTURE_NAMESPACE="develop"
export ROAMINAL_E2E_SSH_FIXTURE_SECRET="roaminal-codespace-authorized"
export ROAMINAL_E2E_SSH_HOST="roaminal-codespace-ssh.develop.svc.cluster.local"

kubectl get deploy/roaminal-codespace svc/roaminal-codespace-ssh \
  secret/roaminal-codespace-authorized \
  -n "$ROAMINAL_E2E_SSH_FIXTURE_NAMESPACE" \
  -o custom-columns=KIND:.kind,NAME:.metadata.name,COMPONENT:.metadata.labels.app\\.kubernetes\\.io/component,MANAGED_BY:.metadata.labels.app\\.kubernetes\\.io/managed-by
```

Continue only when Deployment and Service both report
`component=ssh-test-target`, and the Secret is the explicitly designated
codespace authorization Secret. Record their pre-reset UIDs. Delete only
those exact objects, wait for the Pod to terminate, then run the normal key
creation, Secret creation, and Helm install steps below using release
`roaminal-codespace`. The install turns the pre-provisioned target into a
Helm-owned disposable fixture while preserving its Service DNS name. If any
label, UID, or Secret check differs, report `BLOCKED` and do not delete.

After recording the UIDs and completing the checks, the one-time reset is:

```bash
kubectl delete deployment/roaminal-codespace \
  service/roaminal-codespace-ssh \
  secret/roaminal-codespace-authorized \
  -n "$ROAMINAL_E2E_SSH_FIXTURE_NAMESPACE" --wait
```

Wait until the old Pod is gone before installing the Helm release. The
Service, EndpointSlice, and Pod are deleted as a consequence of these exact
resource deletions; do not issue a namespace-wide or label-only delete.

This adoption is a one-time destructive reset of the test target, not a
permission to modify other Pods or PVCs in `develop`. Subsequent runs use
`helm uninstall` and the exact Secret deletion in this document.

The fixture key is generated by Roaminal and its private half stays in
Roaminal's SSH directory. Only the public half is copied to the Kubernetes
Secret. Do not place a private key in a Secret, command argument, trace, or
report.

## Prerequisites

Complete the main [Playwright deployment gate](../README.md) first. The agent
also needs `kubectl`, Helm, permission to create resources only in the fixture
namespace, and a browser context authenticated to the designated Roaminal
release. The fixture release must be separate from the Roaminal release.

The following commands are examples of the required operations. Replace
values only through the variables above; do not paste credentials into shell
history. Public-key files are temporary and must have mode `0600` even though
they are not secret.

## Reset the fixture

Run this reset before the first SSH case and again before every case that needs
a clean remote home. It removes only resources owned by the fixture release.

1. Confirm the release and resource ownership:

   ```bash
   helm status "$ROAMINAL_E2E_SSH_FIXTURE_RELEASE" \
     --namespace "$ROAMINAL_E2E_SSH_FIXTURE_NAMESPACE" 2>/dev/null || true
   kubectl get deploy,svc,pvc,secret \
     -n "$ROAMINAL_E2E_SSH_FIXTURE_NAMESPACE" \
     -l "app.kubernetes.io/instance=$ROAMINAL_E2E_SSH_FIXTURE_RELEASE" -o name
   ```

   If a resource is present without the release label, stop and resolve the
   ownership mismatch. During the one-time adoption above, the pre-provisioned
   resources are deliberately removed by exact name only; do not delete them
   with a selector.

2. Remove the prior fixture release and wait for its processes to terminate:

   ```bash
   helm uninstall "$ROAMINAL_E2E_SSH_FIXTURE_RELEASE" \
     --namespace "$ROAMINAL_E2E_SSH_FIXTURE_NAMESPACE" --wait || true
   kubectl delete secret "$ROAMINAL_E2E_SSH_FIXTURE_SECRET" \
     --namespace "$ROAMINAL_E2E_SSH_FIXTURE_NAMESPACE" --ignore-not-found --wait
   ```

   The fixture values below disable persistence, so no PVC should remain. If a
   previous run created a fixture-owned PVC, list it by the release label and
   delete only that PVC after verifying it has the fixture release ownership.

3. Remove Roaminal-side state owned by the run. Close all fixture connection
   instances through the UI, delete the test Host block and its tmux option,
   and delete the test-generated key only when its filename and fingerprint
   are recorded as fixture-owned. Never remove another user's Host, key, or
   connection instance.

## Generate and authorize the test key

The SSH cases require an Ed25519 key in Roaminal. The algorithm uniqueness rule
means a dedicated test release must start without an existing test-owned
Ed25519 key.

1. In the authenticated Roaminal UI, open `Connections` and `Keys`. Delete an
   earlier fixture-owned Ed25519 key if one is present, then use `Generate key`
   with algorithm `Ed25519` and a unique filename such as
   `roaminal_e2e_ed25519`. The filename must end in `_ed25519` so it is
   recognized by Roaminal's supported key inventory. Leave the passphrase
   empty; passphrase behavior is tested through the terminal prompt, not
   stored by this fixture.
2. Wait for the key-generation connection to finish. Verify the new key appears
   in the key inventory and record only its `keyId`, filename, and public-key
   fingerprint.
3. Read the public key through the authenticated `GET
   /api/v2/ssh-keys/<keyId>/public-key` endpoint or the visible copy action. Write
   exactly that single line to a temporary file and remove it after the Secret
   is applied:

   ```bash
   umask 077
   export ROAMINAL_E2E_PUBLIC_KEY_FILE="$(mktemp)"
   # The agent writes the public key response to this file without logging it.
   chmod 0600 "$ROAMINAL_E2E_PUBLIC_KEY_FILE"
   ```

4. Create the fixture Secret from the file. The public key must never be put in
   a Helm values file committed to the repository:

   ```bash
   kubectl create secret generic "$ROAMINAL_E2E_SSH_FIXTURE_SECRET" \
     --namespace "$ROAMINAL_E2E_SSH_FIXTURE_NAMESPACE" \
     --from-file=authorized_keys="$ROAMINAL_E2E_PUBLIC_KEY_FILE" \
     --dry-run=client -o yaml | kubectl apply -f -
   rm -f "$ROAMINAL_E2E_PUBLIC_KEY_FILE"
   unset ROAMINAL_E2E_PUBLIC_KEY_FILE
   ```

The Secret must contain one authorized Ed25519 key belonging to this run.
Never append a key to a shared Secret. If the key cannot be generated because
an unowned Ed25519 key already exists, report the fixture as `BLOCKED` and use
a dedicated Roaminal release/PVC; do not delete the unowned key.

## Install the codespace

Install the published Chart with an ephemeral home and no nested container
storage. The empty home is writable and is intentionally destroyed on reset.

```bash
helm upgrade --install "$ROAMINAL_E2E_SSH_FIXTURE_RELEASE" \
  oci://ghcr.io/ben-wangz/k8s-at-home-charts/codespace \
  --version "$ROAMINAL_E2E_SSH_FIXTURE_CHART_VERSION" \
  --namespace "$ROAMINAL_E2E_SSH_FIXTURE_NAMESPACE" \
  --set-string ssh.existingSecret="$ROAMINAL_E2E_SSH_FIXTURE_SECRET" \
  --set persistence.home.enabled=false \
  --set persistence.container.enabled=false \
  --set service.ssh.type=ClusterIP \
  --set updateStrategy.type=Recreate \
  --wait --timeout 300s
```

Do not add a public LoadBalancer or NodePort. Verify the release before using
it:

```bash
helm status "$ROAMINAL_E2E_SSH_FIXTURE_RELEASE" \
  --namespace "$ROAMINAL_E2E_SSH_FIXTURE_NAMESPACE"
kubectl rollout status deployment/"$ROAMINAL_E2E_SSH_FIXTURE_RELEASE" \
  --namespace "$ROAMINAL_E2E_SSH_FIXTURE_NAMESPACE" --timeout=180s
kubectl get pod,svc,endpointslice \
  -n "$ROAMINAL_E2E_SSH_FIXTURE_NAMESPACE" \
  -l "app.kubernetes.io/instance=$ROAMINAL_E2E_SSH_FIXTURE_RELEASE" -o wide
kubectl exec -n "$ROAMINAL_E2E_SSH_FIXTURE_NAMESPACE" \
  deployment/"$ROAMINAL_E2E_SSH_FIXTURE_RELEASE" -- \
  sh -lc 'command -v sshd && command -v tmux && tmux -V'
```

The expected state is exactly one Ready Pod, one SSH Service with a ready
endpoint, OpenSSH listening on port 22, and `tmux` available. If the chart
fullname differs from the release name, use the deployment name shown by
`kubectl get deploy` in subsequent commands.

From a temporary in-cluster diagnostic Pod, verify TCP reachability without a
port-forward. Do not print private data or the authorized key:

```bash
kubectl run roaminal-e2e-ssh-probe \
  --namespace "$ROAMINAL_E2E_SSH_FIXTURE_NAMESPACE" \
  --image=busybox:1.36 --restart=Never --rm -i --quiet -- \
  sh -c "nc -z -w 5 $ROAMINAL_E2E_SSH_HOST $ROAMINAL_E2E_SSH_PORT"
```

## Configure Roaminal

Create the SSH Host through the Roaminal Connection manager. Do not edit the
container filesystem directly. Use these values:

| Field | Value |
| --- | --- |
| Host alias | `ROAMINAL_E2E_SSH_ALIAS` |
| HostName | `ROAMINAL_E2E_SSH_HOST` |
| User | `ROAMINAL_E2E_SSH_USER` |
| Port | `ROAMINAL_E2E_SSH_PORT` |
| IdentityFile | the fixture Ed25519 filename |
| IdentitiesOnly | `yes` |
| StrictHostKeyChecking | `no` |
| UserKnownHostsFile | `/dev/null` |
| ServerAliveInterval | `30` |

For tmux cases, enable the advanced tmux option on a second alias or update
the same alias after the non-tmux cases. Set the session name to
`ROAMINAL_E2E_TMUX_SESSION`. Use the same IdentityFile and SSH fields. The
session name must begin with a letter and contain only letters, digits, `_`, or
`-`.

## Remote-state preparation

Run these commands with `kubectl exec` only against the fixture deployment.
They reset the remote home without affecting Roaminal or another Pod:

```bash
kubectl exec -n "$ROAMINAL_E2E_SSH_FIXTURE_NAMESPACE" \
  deployment/"$ROAMINAL_E2E_SSH_FIXTURE_RELEASE" -- \
  sh -lc 'rm -f /root/.tmux.conf; tmux kill-server 2>/dev/null || true; rm -f /tmp/roaminal-e2e-*'
```

For the custom-prefix tmux case, write only the fixture configuration and
reset the Pod afterward:

```bash
kubectl exec -i -n "$ROAMINAL_E2E_SSH_FIXTURE_NAMESPACE" \
  deployment/"$ROAMINAL_E2E_SSH_FIXTURE_RELEASE" -- \
  sh -c 'cat > /root/.tmux.conf' <<'EOF'
unbind C-b
set -g prefix C-k
bind C-k send-prefix
EOF
```

The tmux case must prove both paths: with no config, Roaminal displays and
sends `Ctrl+B`; with the file above, it detects and uses `Ctrl+K`. Never use a
local Roaminal `.tmux.conf` to satisfy this assertion.

## No-tmux negative variant

The missing-tmux assertion is run only after all positive SSH/tmux cases and
only on the disposable fixture. Rename the binary inside the running fixture
Pod, run the negative case, then reset and reinstall the fixture before any
further positive case:

```bash
kubectl exec -n "$ROAMINAL_E2E_SSH_FIXTURE_NAMESPACE" \
  deployment/"$ROAMINAL_E2E_SSH_FIXTURE_RELEASE" -- \
  sh -lc 'tmux_path="$(command -v tmux)" && mv "$tmux_path" "${tmux_path}.roaminal-e2e-disabled"'
kubectl exec -n "$ROAMINAL_E2E_SSH_FIXTURE_NAMESPACE" \
  deployment/"$ROAMINAL_E2E_SSH_FIXTURE_RELEASE" -- \
  sh -lc '! command -v tmux'
```

Start the tmux connection and assert that Roaminal reports the preflight
failure before publishing an instance. There must be no pending launch, live
instance, or orphan SSH transport. Do not restore the binary in place; run the
full reset/install procedure so the image layer is clean.

## Test order and cleanup

Run SSH and tmux cases serially against this fixture:

1. Reset and install the fixture; create the non-tmux Host and run initial SSH
   connection and transport-reuse cases.
2. Close all test instances, reset remote state, enable tmux, and run tmux
   create/attach, reuse, resize, contextual-keyboard, and pending-launch cases.
3. Run the source-change/draining case only with a writable SSH config and
   only after recording the original ETag. Restore the original Host block
   even when the assertion fails.
4. Run the no-tmux negative variant last, then reset and uninstall the fixture.

After every case, close only instances whose definition ID or alias belongs to
this run, delete the test Host and tmux option, and verify that no pending
launch remains. At the end of the suite:

```bash
helm uninstall "$ROAMINAL_E2E_SSH_FIXTURE_RELEASE" \
  --namespace "$ROAMINAL_E2E_SSH_FIXTURE_NAMESPACE" --wait || true
kubectl delete secret "$ROAMINAL_E2E_SSH_FIXTURE_SECRET" \
  --namespace "$ROAMINAL_E2E_SSH_FIXTURE_NAMESPACE" --ignore-not-found --wait
```

Verify that no fixture-labeled Pod, Service, EndpointSlice, Deployment, or PVC
remains. Delete the fixture-owned Roaminal key only if the suite owns it. Run
the browser diagnostics gate after every launch transition and redact all
terminal output, tokens, and key material from the result.
